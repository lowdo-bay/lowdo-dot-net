# LowDO Website Audit — 2026-03-04

## 1. Structure & File Organization

**Overall: Well-organized. Follows Eleventy conventions cleanly.**

### Strengths
- Clear separation of concerns: `entries/` (content), `_includes/` (templates), `_data/` (config), `assets/` (static)
- Single source of truth for config: `_data/settings.yaml`
- Template files organized into `layouts/` and `components/` subdirs
- CSS/JS kept inside `_includes/assets/` and compiled inline — avoids extra network requests
- Comprehensive `docs/` folder for non-technical editors

### Issues
- **`package.json` name is `halide`** — leftover from a starter template. Misleading.
- **`projects/` dir at repo root** — appears to be a legacy/unused directory alongside `entries/projects/`. Needs confirmation.
- **`stackbit.config.ts` present** — Stackbit CMS shows no active integration in templates or `netlify.toml`. Likely dead weight.
- **`Local Development Workflow.md` at root** — duplicates content already in `docs/`. Could be consolidated.
- **Image caching commented out** (`.eleventy.js` lines 87–92) — re-fetches remote images on every build. Should be re-enabled.

## 2. Content Architecture & Automated Page Creation

**Overall: The system works well. Drop a folder + markdown file, get a page. A few rough edges.**

### How it works
- `entries/projects/` → individual pages at `/project/{slug}/`
- All other entry types → index-only display in `/index/`
- Images auto-discovered by name (`header.jpg`, `thumb.jpg`, or any image in folder)
- Categories and entry types dynamically built from frontmatter — no hardcoded lists
- Template folders (`_template-*`) inside each entry type serve as authoring guides

### Strengths
- Fully automated: add a folder + `.md` file, page appears
- Frontmatter schema is consistent and well-documented
- Dynamic `allCategories` and `allEntryTypes` collections in `.eleventy.js` — filters self-update as content is added

### Issues
- **Content mismatch in `casa-marianella`** — markdown body references "Wolf Creek Ranch" copy, suggesting a copy-paste error during entry creation.
- **`position` field requires manual management** — no guard against duplicate positions. A large number of entries could be hard to sort manually.
- **No slug customization** — slugs are auto-derived from folder names. If an editor renames a project folder, the URL breaks with no redirect. A `slug:` override field would help.
- **`year` vs `date` field relationship undocumented** — projects support both, but the relationship (display vs. sort) is not explained for editors.
- **AVIF disabled by default** (`settings.yaml: avif.enabled: false`) — WebP is enabled. AVIF would meaningfully reduce image sizes but is disabled for compatibility.

## 3. Performance & Accessibility Issues

### Performance

**Strengths:**
- All CSS/JS inlined — zero render-blocking external stylesheets/scripts
- Multi-format images: JPEG + WebP (AVIF available but off)
- Lazy loading on secondary images; eager on header/hero images
- HTML/CSS/JS minified in production
- Preconnect to `fonts.gstatic.com` in `<head>`
- CSP headers auto-generated by Netlify plugin

**Issues:**
- **No `robots.txt`** — without this, crawlers are unguided. Netlify doesn't auto-generate one.
- **No `sitemap.xml`** — standard SEO requirement. No 11ty sitemap plugin configured. Should be added via `@11ty/eleventy-plugin-sitemap` or a simple template.
- **Image cache commented out** (`.eleventy.js` lines 87–92) — should be re-enabled.
- **`base.css` is ~25KB** — contains many spacing utilities that may have low utilization. Could be pruned with PurgeCSS if Lighthouse flags unused CSS.
- **GA4 tracking ID not configured** (`settings.yaml: site_ga4_id` is empty) — analytics silently not running.
- **TODO in `.eleventy.js` line 295**: Google Fonts CSS fetched remotely at build time but font files are not cached locally — acknowledged but unresolved.

### Accessibility

**Strengths:**
- `lang` attribute on `<html>` ✓
- `<main>` landmark present ✓
- `aria-label="Main navigation"` on nav ✓
- `aria-expanded` on mobile menu button ✓
- `prefers-reduced-motion` media query in CSS ✓
- Focus styles on links ✓
- `alt` text derived from `thumbnail.alt` or `title` ✓
- External links use `rel="noopener"` ✓
- JSON-LD structured data present ✓

**Issues:**
- **Show more/less filter toggle is not keyboard accessible** (`_includes/components/indexFilters.njk` line 17) — uses a `<span>`. Needs `role="button"` + `tabindex="0"` + keydown handler, or replace with `<button>`.
- **Mobile menu button lacks visible `:focus-visible` style** — CSS does not explicitly style focus on the hamburger button.
- **Index row titles lack semantic heading** (`_includes/components/indexRow.njk` line 18) — entry names are `<span>` elements. Could be `<h2>` or `<h3>` for screen reader navigation.
- **Gallery images in `project.njk` (lines 96–100) lack `<figure>` wrapper** — `<figcaption>` used without parent `<figure>`, which is invalid HTML per spec.
- **Dark mode toggle JS quirk** (`dark_mode.js` line 18) — targets `.dark-toggle` class to set `.checked`, which is a property only on `<input>` elements. Likely works incidentally but is fragile.
- **Loose equality in `dark_mode.js`** — uses `==` instead of `===`.
- **Category filter container hidden via inline style** (`indexFilters.njk` line 19: `style="display: none;"`) — should use a CSS class.
